One lifecycle. Four steps.

Employment facts become account state.

  1. 01

    Change the employment record

    An HR operator hires, transfers or offboards an employee in Elytra.

  2. 02

    Publish the event

    Elytra records the change in an append-only outbox. Ascendra polls for new events every minute.

  3. 03

    Resolve the identity state

    Ascendra combines employment facts with its own access and deprovisioning decisions.

  4. 04

    Provision and verify

    Microsoft Graph creates, updates or disables the Entra account. Sync results and audit events record the outcome.

Lifecycle cases in the lab

  • JoinerOnboard a new employee and follow the identity into Entra, including future-dated starts.
  • MoverUpdate employment context and review whether existing access still fits the new role.
  • LeaverDisable the account when employment ends, including departures during leave of absence.

The control that matters: a resync must preserve an approved deprovisioning decision. An unrelated HR update must never silently re-enable that account.

Two systems · Separate authority

HR owns employment. IGA owns access.

Elytra and Ascendra each have their own React interface and Convex deployment. They exchange data over an authenticated HTTP API and share no database. Ascendra never writes back into HR.

Inspect the architecture and integration boundaries

The HTTP feed uses a shared integration secret. Ingest keeps a cursor, accepts additive fields, and quarantines malformed events with a critical audit entry. Source event time is retained for audit history and offboarding urgency.

HR reconciliation detects missing identities and divergent records. Findings are deduplicated and reported for review; it does not alter HR records. Account drift and HR drift are separate checks.

Beyond provisioning

Who can change access? Who checks it?

An account pipeline needs controls around the people operating it and the access it leaves behind.

Operator roles → explicit capabilities
SecurityAdmin, AccessAdmin, Auditor and HelpDesk have distinct permissions. Managed employee roles are separate from the roles that let operators use the console.
Maker/checker → another operator approves
A privileged role grant or deprovisioning of a still-employed worker becomes a pending request. The requester cannot approve their own request.
Recertification → keep or revoke
Campaigns snapshot current role holders. Reviewers decide whether access is still needed; unresolved items are revoked when the campaign closes. When the original grantor is recorded, that operator cannot affirm their own grant. Older grants without grantor history cannot enforce this check.
Mapped roles → real membership changes
When a role is bound to an Entra group, revocation schedules a Graph membership removal. The result is logged separately; a local role change does not guarantee successful removal. Without a mapping, the audit trail explicitly records that Entra revocation was not enforced.

Investigation & verification

The useful part was finding where it broke.

An architecture review exposed defects in the integration. I evaluated the findings and verified the original hardening fixes against live deployments, including real Entra membership changes. The later regression fix below is locally tested; deployment and a new live check are pending.

01 / Account state

Deprovisioning was silently reversed.

A later HR event could re-enable a deliberately disabled account. Desired-state resolution uses both HR facts and the IGA decision. A further local regression fix preserves that decision after Graph failure; deployment and live-tenant verification are pending.

02 / Feed resilience

One bad event could stop the feed.

Malformed events now go to a dead-letter queue with a visible critical signal. Valid events continue, and integration health reports failures and lag.

03 / Lifecycle timing

A leaver on leave was missed.

The transition job now includes employees on leave of absence. The original event timestamp also survives ingest instead of resetting the offboarding clock.

04 / Enforcement

A revoked role could leave real access.

Mapped role revocation now schedules Entra membership removal and records the outcome. Unmapped roles produce an explicit unenforced-revocation audit event.

Regression check · 13 October 2026: start with an active employee deliberately deprovisioned in IGA, record a failed disable or session-revocation operation, then resolve desired state again. Expected: the decision stays deprovisioned and account activation stays false. Actual: the automated checks pass; all 45 tests and the Ascendra build passed. This is code verification, not a new live Entra test.

Implementation and current limits

React + Vite frontends, separate Convex backends, an authenticated HTTP outbox, and Microsoft Graph provisioning. Narrow Vitest tests cover desired account state, event normalization and the HR reconciliation diff.

The lab does not implement multi-role identities or a complete role-to-group provisioning and drift subsystem. HR reconciliation is detection-only. These boundaries are documented in the hardening plan.
